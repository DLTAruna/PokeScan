Banc V2 — la chaîne d'identification, telle qu'elle tourne

Ce banc importe scan-v2.js, le module qui tourne sur le téléphone. Il n'en réimplémente rien : régler une copie reviendrait à régler un scanner qui n'existe pas. Corpus : les vraies photos de photos-test/, redressées comme le fait l'application. Pilotable à la souris, ou depuis la console via window.BANC (voir le bas de page).

Réglages de la chaîne

Dégradation de l'image — ce que la caméra ne donne pas toujours

La capture automatique ne choisit plus l'image la plus nette entre deux (retiré en V.2 : inutile pour l'ORB, disait-on). Ces curseurs le vérifient : si la justesse s'effondre au premier flou, la sélection manquait ; si elle tient, elle ne manquait pas.

Lancer

Prêt. Charge l'index pour commencer (~3 Mo la première fois, puis IndexedDB).

Banc de DÉTECTION — quand l'application voit-elle une carte ?

Mesure l'étape d'AVANT l'identification : le détecteur trouve-t-il la carte, et avec quel score ? C'est lui qui décide s'il se passe quelque chose. Des scènes sont fabriquées à partir des illustrations de l'API — fond, échelle, inclinaison, décentrage, bord coupé, lumière — avec la position réelle connue, donc l'erreur mesurable.

Banc de DÉCLENCHEMENT — capturer vite, mais pas n'importe quoi

Le vrai coût pour l'utilisateur n'est pas l'identification (≈1,2 s) mais l'attente avant qu'elle parte. On simule ici des présentations de carte image par image — posée lentement, posée vite, tenue à main tremblante, arrivant de côté, tenue trop loin — puis on fait concourir plusieurs politiques de déclenchement sur les mêmes séquences. Chacune est jugée sur deux chiffres qui s'opposent : le temps qu'elle fait attendre, et la proportion de captures effectivement identifiables.

Téléphone — scanner de vraies cartes

La même chaîne que le corpus, mais alimentée par la caméra. Chaque carte lue attend ton verdict : c'est la seule façon d'obtenir un taux de justesse réel — les journaux de l'application comparent la prédiction à elle-même et annoncent donc toujours 100 %. Tout est conservé sur l'appareil (IndexedDB) et survit à un rechargement.

Pilotage depuis la console

// ── corpus (photos-test/)
await BANC.init()                      // charge l'index, renvoie le moteur retenu
BANC.config({SHORT:30})                // réglages de scan-v2.js (reglagesV2)
BANC.degrader({flou:2})                // dégrade l'image de requête avant identification
await BANC.froid({disque:true})        // vide les caches ORB — mesurer un démarrage à froid
await BANC.lancer(8)                   // passe 8 photos (par paquets : évite les délais d'attente)
BANC.resultats()                       // résumé + détail de la passe en cours
BANC.cloturer('worker off')            // fige la passe et l'ajoute au tableau comparatif
BANC.passes()                          // toutes les passes closes

// ── téléphone (caméra)
await BANC.camera()                    // ouvre la caméra et lance la détection
await BANC.capturer()                  // déclenche à la main
await BANC.etalon()                    // vitesse de l'appareil + batterie
await BANC.appareil()                  // état courant, sans remesurer
BANC.scans()                           // tous les scans caméra conservés
await BANC.envoyer()                   // remonte les scans vers /api/scan-log
BANC.exporter()                        // fichier JSON (photos comprises)
await BANC.viderScans()                // efface l'historique de cet appareil
